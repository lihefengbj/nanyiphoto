# 01 产品方案

修订日期：2026-10-17

状态：按 2026-10-17 决策修订首发为普通用户可用的本地证件照编辑小程序；本文不是上线验收报告。

## 首发决策（2026-10-17）

- 产品名称「南一证件照」，品牌呈现「南一科技」，定位是普通用户可直接使用的证件照编辑小工具。
- 核心链路全部在本机：拍摄 / 选图、裁剪与构图、纯色背景取样 / 抠除 / 手动修边、白 / 蓝 / 红换底，以及像素尺寸、JPEG / PNG、文件大小范围导出；核心编辑不依赖后端，也不上传照片。
- 首发尺寸提供小一寸、一寸、大一寸、小二寸、二寸五种常见打印参考；像素按 300 DPI 换算并明确说明不代表特定证件或办理渠道的官方规格。
- 私有模型对比放在「其他」页，针对同一张照片切换查看原图、本机色键结果和私有模型结果。仅模型步骤会在用户逐张同意后把缩小副本发送到其配置的私有服务；它不是普通编辑的前置条件。
- 微信正式提审仍须完成账号主体 / 类目 / 名称 / Logo、隐私保护指引、相机与相册授权、iOS / Android 真机矩阵和平台审核；仓库测试不代表已提审或已上架。

本文后续云端抠图、审核、COS 与用户规格目录方案保留为未来服务迭代设计，不作为本次本地首发放行条件。

## 1. 背景与竞品分析

参考产品「证件照」小程序的核心链路：

**上传/拍摄照片 → 选规格 → 智能抠图换底色 → 预览微调 → 付费/免费下载高清图**

### 1.1 竞品截图分析（2026-10-14，基于实际界面截图）

**分享卡片**：主打"免费证件照、自动换底色、标准尺寸证件照全支持"，CTA 为「立即制作」。

**首页结构**（自上而下）：

1. 收藏引导横幅（"添加到我的小程序"，提升回访）
2. 大标题 + 卖点："证件照生成器 · 3秒快速生成"
3. 功能卡片区：
   - 主卡片「一寸证件照 25x35mm | 295x413px」（默认最热规格直达）
   - 工具卡片「证件照换底色」（已有证件照仅换背景色的轻量入口）
   - 工具卡片「证件照编辑」（修改文件 KB 大小与 DPI——考试报名照刚需）
4. 「热门证件照尺寸」列表（二寸 35x49mm | 413x579px、小一寸 22x32mm | 260x378px……，mm + px 双标注，列表式）
5. 底部 tabBar：首页 / 小工具 / 电子照 / 我的

**关键结论**：

- 变现以**免费 + 广告**为主（分享卡片明确打"免费"），付费下载不是第一优先级
- 「改 KB / 改 DPI」和「仅换底色」是高频刚需工具，必须纳入产品
- 规格需同时展示毫米与像素，方便用户对照报名系统要求
- 竞品强调生成速度（"3秒"）；本项目先测上传至可用预览的 P50/P95，达标前不将此作为宣传承诺

### 1.2 竞品流程页分析（规格详情 + 上传引导页，2026-10-14 截图）

点击某个规格（如"一寸证件照"）后进入规格详情页，自上而下：

1. **规格说明面板**：规格名称 / 打印尺寸（25*35mm）/ 像素尺寸（295*413px）/ 文件大小要求（"无要求"，部分报名规格限制 20-200KB）/ 分辨率（300dpi）
2. **背景色预选**：7 色色板（深蓝 / 白 / 红 / 浅蓝 / 灰 / 渐变蓝 / 藏青），**在上传照片之前选定**，流程是"先定规格和底色，再传图"
3. **拍照建议**（3 条引导文案）：表情自然抬头挺胸平视前方 / 他人协助用后置摄像头拍摄更佳 / 穿深色衣服、白色或纯色背景墙前拍摄效果最佳
4. **双入口按钮**：「相册选择」（描边次要按钮）/「直接拍摄」（实心主按钮）

**对方案的影响**：

- 规格配置需覆盖打印毫米、像素、文件大小和 DPI；业务约束使用第 2.3 节的结构化字段，竞品的显示字符串不作为存储 / 校验契约
- 用户流程定型为：**选规格（详情页选底色）→ 上传/拍摄 → 抠图合成 → 预览微调 → 下载**
- 拍照引导文案是降低抠图失败率的关键，直接复用此结构

### 1.3 主要功能模块（综合推断）

- 热门规格入口（一寸、二寸、教师资格证、护照、签证、考试报名照等）
- AI 人像分割 + 换背景（白 / 蓝 / 红 / 渐变）
- 已有证件照换底色（轻量独立入口）
- 证件照编辑工具（压缩到指定 KB、修改 DPI）
- 美颜微调、正装换装（增值功能）
- 排版照（6 寸相纸排多张，用于冲印店打印）
- 变现：激励视频广告 / 流量主为主，高清或增值功能可付费

## 2. 产品功能设计

### 2.1 当前首发范围

| 模块 | 功能 | 优先级 | 放行边界 |
| --- | --- | --- | --- |
| 取图 | 相册 / 相机选择，用户确认照片授权 | P0 | 按平台隐私配置与真机权限行为验收 |
| 本地背景处理 | 纯色背景点按取样、边缘连通抠除、容差与手动擦除 / 恢复 | P0 | 适合纯色背景；需验证画质与设备兼容，不承诺自动抠图效果 |
| 常用尺寸 | 小一寸、一寸、大一寸、小二寸、二寸 | P0 | 按 300 DPI 显示打印 / 像素参考，不作为官方渠道规格 |
| 裁剪与换底 | 缩放 / 构图、白 / 蓝 / 红背景 | P0 | 本机完成 |
| 导出 | 目标像素、JPEG / PNG、文件大小范围与相册保存 | P0 | KB 输入按 1 KB = 1024 bytes 换算；保存前读回校验，失败不开放保存 |
| 产品 / 隐私 | 南一科技品牌、隐私说明、相机 / 相册拒绝处理 | P0 | 账号后台和目标设备实测是提审前置 |
| 私有模型对比 | 其他页同图对比本机色键与用户配置模型 | 可选 | 每张图需单独授权，照片副本发送至用户自配私有服务，不作为本地编辑依赖 |
| 云端正式抠图 / 审核 | 受信身份、审核、共享存储与删除闭环 | 后续 | 不纳入当前本地首发目标 |
| 历史记录、广告、排版、美颜 / 换装、冲印 | 独立评估后排期 | 后续 | 本次不实现 |

“规格可选”不等于“保证报名通过”。对禁止数字修改 / AI 编辑的场景，不默认开放抠图、美颜或换装；先核实规则，不能通过尺寸校验替代业务审核。

### 2.2 页面结构

本次首发主流程：首页选择常用尺寸 → 拍摄 / 选图 → 本机编辑 / 换底 → 设置导出格式与文件大小 → 保存相册。另设「其他」页承载可选私有模型对比。核心主流程不展示未核验的草稿规格，不依赖云端任务或模型服务。

四个 tab（首页 / 小工具 / 电子照 / 我的）是后续信息架构；V1 不展示无法使用的小工具、历史记录或支付入口。规格列表同时展示适用渠道和有效年份，不将不同业务的规则合并成一个“通用护照 / 考研”条目。

### 2.3 规格引擎

可执行示例见 [`../config/specs.example.json`](../config/specs.example.json)，字段契约见 [06 接口与验收规范](./06-接口与验收规范.md)。示例全部禁用且为草稿，不作为已核验的上线配置。

| 字段 | 职责 |
| --- | --- |
| `id / name / enabled / verification` | 稳定标识、显示名称、上架开关、核验状态 |
| `usage` | 区分 `print` 打印规格与 `digital` 电子提交规格 |
| `pixels` | 目标宽高、允许的宽高范围、宽高比 |
| `print` | 可空的毫米宽高与 DPI；仅打印规格强制换算校验 |
| `file` | `jpeg / png`、`minBytes / maxBytes`，无约束用 `null` |
| `backgrounds / placement` | 允许底色、可空的头部位置规则，不使用统一头顶 / 下巴比例替代官方要求 |
| `scope` | 地区、年份、提交渠道 |
| `source / updatedAt / expiresAt` | 内部或官方来源、原文地址、核查日期、更新 / 到期日期 |

界面的“25×35mm”“20-200KB”等文案从结构化数据生成，不反向解析显示字符串执行业务规则。字节边界以核验后的整数保存，来源中的 KB / KiB 含义须记录清楚。

打印规格按 `round(mm / 25.4 × dpi)`验证目标像素；电子规格以提交系统的像素 / 格式约束为准，不强制通过毫米换算重写。例如 2 英寸是 50.8mm，展示约 51mm 不代表电子文件应由 600px 改成 602px。

`/api/specs`提供版本号、ETag 和过期信息；客户端保留已验证的随包默认配置及最近有效缓存。离线仍可选规格，云端抠图必须联网。无效或未知版本不覆盖有效缓存；创建任务时固定规格版本，编辑过程中不静默替换规则。

### 2.4 合成与导出规则

1. 高分辨率源图留在本地，仅生成最长边 512-1024px 的推理副本；压缩参数是 PoC 候选，不能保证选图接口始终返回原始质量。
2. 统一图片方向、宽高、色彩处理和裁剪变换。蒙版必须对应方向归一化后的同一图像，记录源图、推理图、画布之间的映射；双指操作与最终导出使用同一组变换参数。
3. 仅 alpha 方案可能保留旧背景的发丝颜色；比较“原图 + alpha”“前景 + alpha”“高分辨率边缘细化”后确定资产契约。低分辨率前景也不能直接冒充高清成品。
4. 灰度 PNG 必须将灰度值映射到 RGBA 的 alpha 通道，不能直接用不透明灰度图执行透明裁剪。契约还须明确预乘 / 非预乘 alpha，避免二次乘 alpha 产生黑边。
5. 显示尺寸、渲染缓冲尺寸和文件导出尺寸分开管理。使用 `wx.canvasToTempFilePath`，最终 `destWidth / destHeight`是规格目标像素，不能按屏幕 DPR 或统一 2 倍放大成品。
6. 导出后重新读取文件，验证实际宽高、格式与字节数。JPEG quality 搜索有迭代上限和最低可接受画质；无解时明确提示，不能擅自缩小固定像素、加无意义填充或保存不合格文件。
7. DPI 是文件密度信息，不是放大像素。单独验证元数据写入及保存相册后的保留情况；若相册链路会改变文件，提供经验证的文件交付方式或关闭该渠道的 DPI 保证。

## 3. 技术架构

```text
原生小程序（WXML / WXSS / JS 或 TS、Canvas 2D）
  ├─ 本地高分辨率源图 → 方向归一化 → 小尺寸推理副本
  ├─ 申请限定对象的上传凭证 → 直传私有 COS
  ├─ callContainer 发送任务 JSON → 有上限的状态轮询 / 取消
  └─ 仅 ready 时取得短时资产地址 → 合成 → 精确导出 → 保存

FastAPI 单服务（Docker，微信云托管优先）
  ├─ 上传登记、归属校验、限流、规格配置
  ├─ 持久化任务记录、幂等、有限队列、租约 / 超时
  ├─ 内容安全异步提交 / 回调与模型推理并行
  ├─ 模型适配器、前景 / alpha 后处理、受控商用兜底
  └─ 审核放行、对象主动删除、定期补偿清理、指标

私有 COS：输入 / 审核副本 / 输出素材，短时授权，生命周期兜底
共享持久化任务存储：M0 选型；不得依赖容器本地文件或进程内状态上线
```

具体路由、任务状态与验收矩阵见 [06 接口与验收规范](./06-接口与验收规范.md)。V1 不建立订单 / 支付服务，也不引入独立 Node 业务服务或消息中间件；只有容量数据证明必要时再拆分。

### 3.1 模型与运行方式

- 已确定的是“自部署候选模型 + 可关闭的商用兜底”方向，RVM / PP-HumanSegV2 / MODNet 尚未定稿。
- 在目标 CPU / 内存实例上，用同一组至少 50 张获授权测试图比较最终成品质量、P50/P95、峰值内存、启动 / 预热与并发能力。RVM 的视频测速不作为低配 CPU 单图性能依据。
- 建立代码、预训练权重和依赖许可证清单，记录版本、来源、哈希及部署 / 分发方式。RVM 仓库采用 GPL-3.0；这不等于禁止商用，但必须核实所用代码和权重的实际义务。
- 模型 session 启动预加载、预热；推理不阻塞事件循环。线程池、ONNX 内外部线程数、进程数统一调优，避免每个 worker 复制模型造成内存超限。
- 从推理并发 1 开始测量，用有限队列和任务总截止时间控制负载；不能将“调用不限次”等同于无限吞吐。
- 商用适配器输出统一素材 / 坐标 / alpha 语义。按明确的可恢复错误触发，超时、重试、熔断、每日金额上限均可配置；不假设有可靠的自动“发丝效果差”评分。

### 3.2 上传、鉴权与清理

- 图片与抠图素材走对象存储，业务接口只传小 JSON，不以内嵌二进制或 base64 规避请求 / 响应限制。M0 核实当前 SDK、网关、上传和超时限制并记录；异步任务不依赖单次调用一直等待推理完成。
- 从受信入口解析用户身份；禁止信任客户端提交的 `openid`或任意同名 Header。云托管公网入口必须关闭或采用等效鉴权，防止伪造平台身份。
- 上传凭证绑定用户、任务和指定对象，只允许所需操作；客户端的 `fileID`不能直接授权服务端下载，必须与上传登记和 owner 匹配。
- 私有桶、HTTPS、限定服务端角色权限；输出短时签名地址仅发给已授权且审核通过的任务。业务服务不接受任意外部图片 URL。
- 审核和推理结束后主动删除输入及审核副本；未上传、未提交、失败、取消、超时、过期任务均有补偿清理。输出素材到期自动清理，用户主动保存的本地成品不作为云端历史库。
- COS 生命周期每日扫描且异步执行，只作兜底，不能据此承诺 24 小时内删除。具体保留时间、补偿频率、删除告警及对外说明在上线前与实测结果一致。

### 3.3 网络与存储边界

客户端分别封装 `IdentityProvider / ObjectStorage / TaskAPI / SpecRepository`；后端使用对应身份和存储适配器。云托管迁移自建需重新验证登录态、域名与证书、上传权限、回调地址、数据迁移、限流和清理，不承诺“只改配置”。

任务存储需支持 owner 查询、唯一幂等键、条件更新、回调去重、任务 / 清理租约，多实例共享且重启后可恢复。M0 在云数据库候选中按实际成本和所需能力选型；不能因为保持单服务而省略持久化。

## 4. 安全与合规

1. 个人主体为当前业务选择，但类目、广告、支付资格须以账号后台当期规则核实。不得靠调整措辞认定实际功能不受相关规则约束。
2. 照片仅用于用户请求的处理，不用于训练、身份比对或建立人脸特征库；测试集另行取得授权。隐私说明覆盖用途、云端处理、第三方审核 / 兜底、保留时间、用户清理和权利请求入口。
3. 上传前完成必要的隐私告知 / 授权；商业兜底涉及新的接收方时按适用规则完成告知，不将“已配置 SDK”当成合规证明。
4. `mediaCheckAsync`的返回任务标识只代表提交成功。维护审核与推理两套状态；审核通过且推理成功才放行预览、资产下载、保存或分享。审核超时 / 错误不默认通过。
5. 验证平台回调，关联检测标识和任务，支持重放、重复及乱序事件；拒绝、取消、过期任务不能被迟到的通过回调重新激活。
6. 限制原始字节数、解码后像素数、允许格式、请求频率及第三方费用；日志和指标不记录照片、完整签名 URL、凭证或身份敏感信息。
7. AI 标识、深度合成 / 算法备案按实际功能和适用规则逐项评估，V1 也应评估抠图换底的适用性。不得统一断言“只有 V2 需要”或“任何美颜都必须相同水印”；适用显式 / 隐式标识及例外的处理需有依据和审核记录。
8. 用于证件提交时，来源对图像修改的禁止性要求优先于产品功能。未经用途审核的规格禁用；不宣传“保证通过”，不通过去掉法定标识满足文件要求。

## 5. 性能、成本与变现

端到端耗时从用户确认取图后开始，计入方向处理、压缩、凭证、上传、排队、审核、推理、素材下载和首次可用合成。分别记录各阶段及整体 P50/P95，并区分正常网络、弱网、设备、图像大小与并发；未满足条件前不宣称“3 秒生成”。

成本按同一计费周期计算：

```text
单次成功成本 =
（常驻算力 + 数据库 + 存储 / 请求 / 流量 + 审核 + 商用兜底 + 其他必需服务）
÷ 成功生成次数
```

失败和重试消耗也进入分子。使用当前实际报价 / 账单，免费额度单独列出，不将旧刊例价或优惠当成长期成本。设置并发、用户频率、商用预算和费用告警，按低 / 中 / 峰值流量预测，而非预设兜底费用可忽略。
