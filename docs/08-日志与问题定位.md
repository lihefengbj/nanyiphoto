# 08 日志与问题定位

实现日期：2026-10-16。用于当前 local / test 工程，不解除生产启动门禁。

## 1. 输出与配置

后端使用标准库 logging，输出一行一条 JSON。默认控制台 + `.data/logs/api.jsonl`，
文件及备份在 `.data/` 内，已被 Git 忽略；不增加日志查询 API 或远程采集。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `NP_LOG_LEVEL` | `INFO` | `DEBUG / INFO / WARNING / ERROR` |
| `NP_LOG_CONSOLE` | `true` | 严格使用 `true / false` |
| `NP_LOG_FILE` | `.data/logs/api.jsonl` | 置为空字符串可关闭文件输出 |
| `NP_LOG_MAX_BYTES` | `1048576` | 单文件轮转阈值，允许 4096 字节至 10 MiB |
| `NP_LOG_BACKUP_COUNT` | `3` | 保留 1–10 个备份 |

默认当前文件加 3 个备份约最多 4 MiB。只按大小轮转，没有按天删除功能；
备份可能仍含较早的脱敏诊断记录。需要时在停止服务后主动清理日志。
当前文件轮转用于单进程本地运行，不作为多进程共享文件或云端日志方案。

启动命令务必附加 `--no-access-log`。应用日志只记录路由模板，
而 Uvicorn 原生访问日志可能输出原始路径 / 查询参数；其他第三方日志也不在本模块的白名单控制范围内。
不要为了调试开启请求体、HTTP Authorization 或 SQL 参数输出。

小程序 `miniprogram/config.js` 的 `diagnostics.enabled` 默认 `false`。
开启后输出到控制台和内存环形缓存，默认 100 条，最多可设 200 条；记录只含有界标量，不含嵌套业务对象。
不写相册或本地文件，不自动上传日志。关闭开关会清空内存缓存，
但不会清除开发者工具已经显示的控制台内容；测试结束应关闭并手动清理控制台。

## 2. 关联一次问题

每次 HTTP 请求由服务端生成随机 `requestId`，返回 `X-Request-ID`，包括 401、404、422 和 500。
不会复用客户端提交的同名 header。请求 context 在退出时重置，
同步线程池可使用该 context，独立后台 worker 不继承已结束请求的标识。

小程序网络异常保留安全的 `requestId` 和 `statusCode` 属性：

```javascript
try {
  await api.getSpecs()
} catch (error) {
  // 只取安全字段，不打印原始请求、响应或完整 error 对象。
  const evidence = { code: error.message, requestId: error.requestId, status: error.statusCode }
}
```

在开发者工具中查看当前缓存：

```javascript
getApp().diagnostics.configure({ enabled: true, level: "INFO", maxEntries: 100 })
getApp().diagnostics.snapshot()
```

然后使用返回的服务端 requestId 过滤后端日志：

```powershell
Get-Content .data/logs/api.jsonl -Tail 100
# 将下面的占位文字替换为实际返回的 requestId。
Get-Content .data/logs/api.jsonl | Select-String '实际返回的requestId'
```

同一次创建任务请求的 `task.created` 事件包含 `requestId` 和 `taskRef`。
后续推理、审核、取消和清理通过相同 `taskRef` 关联，而不是把审核 traceId 当作请求追踪标识。
`taskRef / uploadRef` 是随机资源 UUID 的 SHA-256 前 24 位；
不对低熵用户身份做哈希，不记录原始 owner、taskId、uploadId 或审核事件标识。

## 3. 事件与证据

| 事件组 | 典型记录 |
| --- | --- |
| `http.request` | 路由模板、方法、状态、耗时、requestId、白名单错误码 |
| `upload.*` | 登记、上传成功 / 失败、图片宽高、归一化字节数、uploadRef |
| `task.*` | 创建、幂等复用、状态转换、取消、taskRef |
| `moderation.*` | 收到、重复、忽略、冲突；不代表已接真实微信审核 |
| `inference.* / worker.*` | 开始、完成、丢弃、失败、租约恢复 / 耗尽 |
| `cleanup.*` | 删除完成、失败、尝试次数；空扫不输出成功事件 |
| `service.* / maintenance.failed` | 启停、后台维护异常 |
| 小程序 `network.* / privacy.* / lab.*` | 网络、隐私操作、取图、导出读回、保存 / 清理结果 |

2026-10-17 的导出补齐批次在 `lab.export_completed` 中增加有界 `attempts / quality` 标量，
记录实际编码次数和 JPEG quality；PNG 不记录 quality。中间文件移动 / 删除失败仍只记录固定错误码，
不记录源图、私有中间文件路径或原始平台错误。

后端未预期异常对外返回通用 `INTERNAL_ERROR`，日志保留白名单异常类型和最多 8 个项目模块 / 行号。
不写异常原文、异常链消息、堆栈源代码、局部变量或绝对文件路径。
输出失败不改变鉴权和任务结果；启动时文件不可用会尝试在控制台记录安全错误。

响应已经发出后的流式或后台异常无法撤回既有响应：
日志 `status` 标记失败，`responseStatus` 记录已发送的 HTTP 状态。当前制作流程不依赖流式输出。
日志不是审计账本；部分状态事件记录发生在事务内，应结合实际任务查询判断最终提交结果。

## 4. 明确禁止与限制

- 不记录照片字节、Base64、完整图片哈希、临时图片路径、签名地址或查询参数。
- 不记录 Authorization、开发令牌、Cookie、密钥、owner / OpenID 或原始请求 / 响应对象。
- 日志字段采用白名单，未知事件与错误文本降级为通用标识；不靠替换几种敏感字段实现脱敏。
- 不打印 Provider 异常原文；需要新增错误原因时，新增固定错误码和对应测试。
- 当前不包含远程日志收集、告警、日志 TTL、云端指标平台或微信真机验证。
- 真实模型、正式审核和云存储尚未接入，测试日志不能作为这些链路已通过的证据。
