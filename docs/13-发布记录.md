### CI 和构建产物

`.github/workflows/ci.yml` 支持 `push`、`pull_request` 和 `workflow_dispatch`。
在同一提交上执行固定解释器 / Node、依赖、真实 Linux ORT CPU、测试、静态及 API 冒烟，
全部成功后才构建并上传：

- 后端 `nanyiphoto_api-0.2.0rc1-*.whl`。
- `nanyiphoto-miniprogram.zip`：从 Git 提交生成的开发者工具源码包，
  包含小程序、项目配置、草稿规格及文档，不是已签名的微信发布包。
- `SHA256SUMS`：wheel / ZIP 的 SHA-256 校验和。

Actions 产物名为 `nanyiphoto-build-<run_id>`，保留 14 天。
GitHub Release 的源码归档是版本快照；CI 检查通过不启用任何正式规格、不发布小程序、
不部署服务、不发送照片。
模型权重、照片、`.data/`、开发令牌、私有配置和日志不入提交 / Release / CI；
用户本机 `project.config.json` 的无关改动保留在工作区，不纳入本次提交。
