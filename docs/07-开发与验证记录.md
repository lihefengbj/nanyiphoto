## 2. 本地与生产的明确差异

- `NP_ENV`只允许 `local / test`；生产值立即拒绝启动。
- 本地开发令牌由开发者自行设置，不能信任 `X-WX-OPENID`或请求体 owner。
- 本地文件上传为受鉴权、限量的原始 PUT。COS 直传必须另行实现，不能把此路由放进云托管图片请求体。
- SQLite 事务通过 `BEGIN IMMEDIATE`串行化本地容量、幂等和状态写入；不能据此证明云数据库多实例实现已验收。
- 本地素材 URL 需每次附带 Bearer 令牌并重新检查任务状态，不是云端短时签名 URL。
- 审核接口关闭，内部 `moderate()`仅供已验证 Provider 接入与测试，不能直接公开成批准照片的接口。
- 当前后台维护只做本地补偿清理和单步 worker，没有正式平台回调、生产清理告警或商用兜底。

```powershell
npm run check

```

```powershell

.\.venv\Scripts\python.exe -m ruff check backend
.\.venv\Scripts\python.exe -m ruff format --check backend
```

## 4. 后续放行门禁

1. 首发规格：提供直接来源、核验者和适用性证据，明确允许编辑后再启用；不为演示把护照 / 签证草稿改成 `verified`。
2. 模型：取得用于本地评估的权重和许可确认，再记录哈希并开展目标实例 / 最终成品 A/B。
3. 正式审核：接入实际提交 / 回调认证，验证提交标识、重复 / 冲突 / 迟到事件、取消和过期。
4. 云资源：实现受信身份、限定对象上传凭证、共享任务记录 / 租约、私有素材和删除可观测性。
5. 真机：验证隐私、取图方向、Canvas、相册授权与导出后文件 / DPI，记录设备与版本。
6. 生产：通过 docs/06 中对应验收及账号 / 隐私 / 用途审查，才解除生产启动门禁；不只改一个环境变量发布。
