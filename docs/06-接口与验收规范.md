# 06 接口与验收规范

修订日期：2026-10-16

状态：最终接口与验收契约。部分接口 / 状态已在本地 FastAPI 实现并验证；私有 COS、受信微信身份、共享数据库和正式审核仍未实现，不能称为生产服务。已实现边界和本地阈值见 [07 开发与验证记录](./07-开发与验证记录.md)，生产阈值需在 PoC 后定稿。

## 1. 规格契约与发布门禁

[`../config/specs.example.json`](../config/specs.example.json)是唯一规格示例文件；不在其他文档复制第二份 JSON。校验工具见 [`../scripts/validate-specs.mjs`](../scripts/validate-specs.mjs)。

目录对象包含 `schemaVersion`、`version`、`updatedAt`和非空 `specs`数组。每条规格要求：

- 稳定且唯一的 `id`、显示 `name`、布尔 `enabled`和 `draft / verified`核验状态。
- `usage: print / digital`；`pixels`包含目标宽高、最小 / 最大宽高和整数宽高比。固定尺寸的上下限与目标相同；电子规格严格匹配比例，仅打印规格允许毫米换算导致的最多一像素偏差。
- `print`为 `null`或 `{widthMM, heightMM, dpi}`。打印用途强制非空并校验四舍五入换算；电子用途可引用打印信息，但不强制等式一致。
- `file`包含 `format: jpeg / png`、可空的整数 `minBytes / maxBytes`，约束边界均为包含端点。
- 非空 `backgrounds`使用 `#RRGGBB`颜色值；复杂渐变另行扩展 schema，不将预设名字当实际颜色。
- `placement`可空；有明确依据时填写 `headTopRatio / headHeightRatio`的最小最大值。未检测人脸 / 头部时不宣称自动验证该约束。
- `scope`包含地区、可空年份、渠道；`source`包含 `internal / official`、标题、可空原文 URL 与核查日期；每条有 `updatedAt / expiresAt`。
- `editingPolicy: pending_review / allowed / disallowed`及说明 `notes`，用于记录该用途是否允许本产品的编辑流程；不能仅凭尺寸满足条件启用。

发布规则：

1. 结构 / 类型 / 数值、唯一 ID、范围、比例、打印换算和日期检查必须通过。
2. 启用规格必须 `verified`、未到期、来源核查信息齐全，并且 `editingPolicy=allowed`。数字用途须提供官方 HTTPS 来源。
3. `--release`要求目录中至少有一条启用规格，避免发布空可用列表。草稿可留在仓库，但服务不下发为可用规格。
4. 有权威来源、`verified`或 `allowed`标签不等于自动取得法律 / 平台认可；核验者另存来源原文和适用性检查记录，工具仅验证这些字段的一致性。
5. 创建任务由服务端验证规格仍启用、未过期，固定目录版本与规则快照。运营紧急禁用应阻止新任务；如涉及安全或用途问题，阻止旧任务结果放行。

日期采用 `YYYY-MM-DD`，校验工具按 UTC 日期计算；`expiresAt`为首个不可用日期，上线服务采用相同规则，避免端 / 服务端到期边界不一致。

## 2. V1 接口

接口统一从受信身份层取得 owner，不接受请求体的 owner / openid 作为鉴权。除平台审核回调和健康检查外，用户接口均检查身份与资源归属。

| 方法 / 路由 | 职责 | 关键约束 |
| --- | --- | --- |
| `GET /api/specs` | 可用规格与目录版本 | ETag / 304；不返回未核验、禁用、过期或用途未放行条目 |
| `POST /api/uploads` | 创建上传登记与限定对象凭证 | 返回 uploadId、指定对象、过期及大小限制；不授予整桶读写 |
| `POST /api/matting` | 创建抠图任务 | uploadId、specId、specVersion；客户端幂等键；返回 202 / 任务标识，不同步等待完整结果 |
| `GET /api/tasks/{taskId}` | 查询双状态与结果 | owner 验证；只在 ready 时返回短时素材地址 |
| `DELETE /api/tasks/{taskId}` | 取消 / 撤销并安排清理 | 幂等；ready 后也可撤销，不能撤回已交付本地文件 |
| `POST /api/callbacks/moderation` | 平台检测结果 | 验证当期平台认证协议、关联 traceId、去重及条件更新 |
| `GET /health/live` | 进程存活 | 不暴露版本、配置或凭证等敏感信息 |
| `GET /health/ready` | 可服务探针 | 模型预热、任务存储可用；不得仅因 HTTP 进程启动就返回 ready |

上传与任务创建顺序：

1. 完成隐私授权后申请 uploadId；服务端将 owner 与待上传对象绑定并持久化。
2. 客户端上传方向归一化的推理副本。COS key / fileID 仅是对象定位符，不是权限证明。
3. 创建任务前校验指定对象确已上传、仍有效，检查真实格式、字节和解码像素数；禁止获取任意外部 URL、任意桶或其他 owner 的对象。
4. 固定输入对象版本 / ETag 并防止提交后覆盖；不能仅给可覆盖原 key 的上传凭证，然后推理时盲读新对象。
5. 对同一 owner + 幂等键 + 同一请求返回同一 taskId；相同键的不同输入 / 规格请求返回冲突，防止错误复用。
6. 未提交上传、幂等保留期、任务 deadline、队列容量、凭证 TTL 与结果 TTL 在 PoC 后固定并覆盖过期测试。服务端执行限制，客户端参数不能放宽。

容量满使用明确的 `QUEUE_FULL / RATE_LIMITED`错误及重试提示；不可恢复输入错误不自动重试。所有自动重试均限制次数和总时间。

## 3. 持久化状态与放行

至少记录：

```text
taskId / owner / uploadId / idempotencyKey / requestHash
specId / specVersion / specSnapshot
inputObject / objectVersion / normalizedWidth / normalizedHeight
moderationStatus / traceId / callbackEventId
processingStatus / modelVersion / attempt / lease / deadline
assetRefs / expiresAt / revokedAt
cleanupStatus / cleanupAttempts / cleanupLastError / deletedAt
createdAt / updatedAt
```

双状态：

| 子状态 | 可用值 |
| --- | --- |
| `moderationStatus` | `pending / approved / rejected / timed_out / error` |
| `processingStatus` | `queued / running / succeeded / failed / cancelled` |
| 对外 `state` | `pending / ready / rejected / failed / cancelled / expired` |

审核与推理可并行。对外只有 `moderationStatus=approved`、`processingStatus=succeeded`、未撤销、未过期且素材完整时为 `ready`。未达到条件时不返回成品、前景、蒙版或其访问地址；原始图是客户端自己的输入，不作为已审核成品展示。

示例（审核尚未完成，服务不返回 assets 字段）：

```json
{
  "taskId": "example-task",
  "state": "pending",
  "moderationStatus": "pending",
  "processingStatus": "succeeded",
  "specVersion": "2026-10-16-draft"
}
```

终态优先与竞态约束：

- 取消 / 撤销、过期、审核拒绝优先于放行；数据库条件更新确保迟到回调不能重新激活。
- 回调先验证来源，再用 traceId 查关联；未知标识不附着到任意任务。重复回调不能重复调用模型或发放资产。
- 通过回调不覆盖已拒绝结果；矛盾或未知回调隔离告警，不默认通过。
- 推理完成时再次检查任务是否有效；已取消的计算即使无法立刻停止，也丢弃 / 删除产物，不再次触发兜底。
- 任务 / 清理 worker 使用租约和条件更新，多实例与进程重启后可恢复；过期租约可接管，不盲目重跑已成功的付费步骤。
- 审核超时 / 错误不放行；可恢复错误按上限重试，截止后失败并清理。

## 4. 素材与坐标契约

由 PoC 决定 `alpha`、`foreground_alpha`或经细化素材的最终模式。每个结果至少声明：

- `assetMode`、素材宽高、方向归一化后的参考宽高。
- 原图 → 推理副本的完整变换；若有 padding / crop，包含偏移与裁剪信息，不能只返回一个缩放倍数。
- alpha 的位深 / 通道、灰度到 alpha 的映射；前景的色彩处理与预乘约定。
- 模型版本、资产到期时间；短时 URL 不进入长期缓存。

客户端必须以同一变换实现预览、拖动 / 缩放和最终导出。仅 alpha 模式测试边缘颜色污染；前景模式测试低分辨率放大、细节和二次预乘。素材模式变更需版本化，不能让客户端靠猜测处理。

输出素材保持私有；URL 即使很短也属于 bearer 凭证，TTL 不能超过任务 / 素材的剩余有效期。注销、撤销、拒绝或过期后停止签发并删除对象；已签发 URL 及本地副本的撤回限制应在设计和隐私说明中如实说明。

## 5. 清理与可观测性

- 审核与推理都不再需要输入时主动删除输入 / 审核副本，第三方读取尚未完成前不能提前删。
- 任务失败、拒绝、取消、未提交或过期时统一安排对象清理；输出到期主动删除。
- 删除失败记为待重试，不假报成功；补偿扫描带租约，重复删除应幂等。
- 生命周期只作兜底。云桶如启用版本、复制或额外备份，删除策略需覆盖相关副本；任务数据库备份只含必要元数据，不写照片或完整签名 URL。
- 清理记录保留必要时间用于审计，不保留原始照片；对外承诺与实际恢复 / 重试上界一致。
- 指标：各阶段与整体 P50/P95、队列 / 拒绝、超时、审核积压、兜底次数 / 金额、未清理对象数量 / 年龄和删除失败。日志仅含脱敏任务标识与错误码。

## 6. 验收矩阵

本地结构、任务状态、权限 / 幂等、清理与 API 冒烟证据见 07；以下涉及云环境、模型和真机的项目仍未执行。本地 fixture 通过不能代替对应真实验收。

| 类别 | 用例 | 通过条件 |
| --- | --- | --- |
| 规格结构 | 缺字段、重复 ID、非法日期 / URL、错误比例 / 范围 / 字节数 | 校验失败且发布被阻止 |
| 规格发布 | 草稿启用、过期、缺官方来源、用途未核验、空可用目录 | `--release`及服务端阻止使用 |
| 打印 / 电子 | 295×413 打印、600×600 电子且打印约 51mm | 分模式校验，不把电子目标改为 602px |
| 方向 / 坐标 | 横竖旋转、不同来源、crop / padding、双指缩放与重置 | 蒙版与人物对齐，预览与导出一致 |
| 成品画质 | 发丝、眼镜、白 / 红 / 蓝新背景、透明边缘 | 无明显旧背景污染、黑边或不可接受细节损失，保留对比文件 |
| 精确导出 | 固定 / 范围像素、DPR 1/2/3、JPEG / PNG、大小上下限 | 最终文件满足目标 / 约束，禁止统一 2x 文件像素 |
| 压缩无解 | 固定尺寸下最低可接受画质仍超限 | 有明确失败提示，不保存伪合格文件 |
| DPI | 写入后、保存相册后、文件分享后 | 实际文件满足要求，否则撤销该渠道的保证 |
| 鉴权 | 伪造身份、他人 uploadId / taskId、任意桶 / URL、覆盖输入 | 拒绝且不泄露或处理其他用户素材 |
| 输入限制 | 超大字节 / 像素、伪扩展名、损坏、未知格式 | 有界资源和明确错误，不压垮实例 |
| 异步审核 | 提交成功、未通过、拒绝、超时、重复 / 乱序回调 | 仅审核通过且推理成功时可拿素材；迟到事件不复活 |
| 幂等 / 恢复 | 重复点击、请求重试、容器重启、多个 worker 接管 | 同请求同 taskId；不重复收费 / 放行；状态可恢复 |
| 取消 / 过期 | 上传后退出、推理中取消、ready 后撤销、素材过期 | 停止放行与兜底，安排清理；前端停止轮询 |
| 删除 | 主动删除失败、补偿失败、无提交上传、版本桶 | 可重试、可审计、触发告警，不只依赖生命周期 |
| 性能 / 容量 | 正常 / 弱网、单用户 / 目标并发、冷 / 热启动 | 分阶段与整体 P50/P95、内存和容量报告，不遗漏审核 / 上传 |
| 兜底 / 费用 | API 故障、适配差异、重复重试、金额到顶 | 输出语义一致、超时 / 熔断 / 预算生效；安全错误不付费重试 |
| 配置 / 设备 | ETag / 304、离线选规格、旧 / 未知版本、低内存、权限拒绝 | 有效缓存不被坏配置覆盖，降级 / 提示明确 |
| 隐私 / 用途 | 未授权、禁止编辑的场景、标识 / 平台材料 | 未获允许不上传 / 不上线，留有适用性核查依据 |

CI 首阶段运行规格示例和校验器测试；应用单测、导出读回、真机与云端集成测试需随工程补齐，不能以规格测试替代整体验收。
