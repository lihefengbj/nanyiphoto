# 05 技术评审（V1 方案）

评审日期：2026-10-14
评审对象：docs/01-03（产品方案 / 实施计划 / 环境依赖）
结论：**方案整体合理，选型克制务实；评审发现 4 项必须修正的问题与若干优化项，已全部落实到文档。**

## 总体评价

- 客户端 Canvas 2D 合成、服务端只做抠图：正确，带宽算力双省
- 自部署 RVM + 商用 API 兜底：成本结构匹配"免费+广告"（云托管 0.5核1G ≈ 43 元/月、1核2G ≈ 86 元/月刊例价，首环境送 3 个月免费额度）
- 原生小程序 + 规格 JSON 引擎 + /api/specs 热更新：正确
- 个人主体 + 广告变现先行：对齐竞品"免费"策略

## 评审意见与落实情况

### P0 必须修正（已落实）

| 评审意见 | 依据 | 落实 |
| --- | --- | --- |
| 上传链路与 callContainer 限制冲突：照片不能走请求体（≤100KiB/≤1MB/≤15s，官方不建议请求中带图片） | 微信云托管官方文档 | docs/01 架构图改为「客户端压缩 → COS 直传 → callContainer 传 fileID → 服务端拉图推理」；COS 升级为链路必需组件（docs/01/02/03） |
| 抠图接口返回 alpha 蒙版而非透明 PNG，客户端用本地原图合成 | 响应 ≤1MB 限制 + 带宽/清晰度优化 | docs/01 关键技术决策 + docs/02 M1 后端任务 |
| 内容安全检测接口过时：imgSecCheck v1 限制 ≤1M、≤750×1334，原图送检报错 | 微信官方文档 | 改用 mediaCheckAsync、小图送检（docs/01/02/03） |
| 后端并发模型缺失：同步 onnx 推理阻塞事件循环 | FastAPI 单事件循环特性 | 线程池推理 + 模型预加载预热 + 并发限流写入 docs/02 M1 |

### P1 建议优化（已落实）

| 评审意见 | 落实 |
| --- | --- |
| "单张 CPU 推理 <1s"需实测；M1 先做模型基准测试（RVM vs PP-HumanSegV2 vs MODNet） | docs/01/02/04 新增基准测试任务与待决策项 |
| V2 换装/美颜的 AIGC 标识合规：《人工智能生成合成内容标识办法》2025-09-01 施行，显式+隐式双标识，深度合成算法备案 | docs/01 合规要点第 5 条；docs/02 新增 AI 标识模块任务与风险行 |
| 规格数据可运营：source/updatedAt 字段、按省细分、mm↔px↔dpi 校验脚本 | docs/01 规格引擎 + docs/02 M0 |
| "迁移无改造成本"过于乐观：自建后调用方式需换 wx.request + code2session | docs/01 网络层抽象决策 + docs/03 部署方案修订 |
