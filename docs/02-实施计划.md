# 02 实施计划

## 里程碑总览

| 里程碑 | 目标 | 预计周期 |
| --- | --- | --- |
| M0 准备 | 注册小程序、搭建工程骨架、规格 JSON 定稿 | 2 天 |
| M1 核心链路（V1 MVP） | 上传 → 抠图 → 换底 → 规格合成 → 保存相册 | 1.5 周 |
| M2 变现与体验（V1.1） | 广告解锁 / 支付、编辑微调、错误处理与引导 | 1 周 |
| M3 增值功能（V2） | 排版照、美颜、换装、冲印 | 2 周 |

## 任务拆解

### M0 准备（2 天）

- [ ] 注册微信小程序（主体、类目：工具-图片处理）
- [ ] 初始化小程序工程（目录结构、 lint、CI 预览上传）
- [ ] 申请云托管环境 + COS 桶
- [ ] 整理 20-50 种热门规格 JSON（尺寸、DPI、允许底色）

### M1 核心链路（约 7-8 个工作日）

后端：

- [ ] 部署 RVM 人像分割服务（FastAPI + onnxruntime，CPU 推理）
- [ ] `/api/matting`：接收图片 → 返回透明底 PNG（异步轮询或同步 <3s）
- [ ] `/api/specs`：规格配置下发
- [ ] COS 临时存储 + 24h 生命周期规则

小程序端：

- [ ] 首页：规格宫格 + 搜索
- [ ] tabBar 框架：首页 / 小工具 / 电子照 / 我的
- [ ] 规格详情页：说明面板（毫米/像素/文件大小/DPI）+ 背景色预选 + 拍照建议 + 相册/拍摄双入口
- [ ] 上传页：`wx.chooseMedia` + 拍摄引导框 + 图片压缩
- [ ] 编辑页：Canvas 2D 合成（底色层 + 人像层），拖动/双指缩放
- [ ] 下载页：`canvas.toTempFilePath` → `wx.saveImageToPhotosAlbum`
- [ ] 规格带 fileSize 限制时，下载自动压缩到目标 KB（二分 quality）
- [ ] 内容安全检测接入

联调验收：

- [ ] 10 种标杆规格端到端跑通（一寸/二寸/护照/美签/教资/考研等）
- [ ] 弱网、大图（>10MB）、授权拒绝等边界场景处理

### M2 变现与体验（约 5 个工作日）

- [ ] 小工具 Tab：已有证件照换底色（轻量流程）
- [ ] 小工具 Tab：压缩到指定 KB（二分调整 JPEG quality 逼近目标大小）、修改 DPI
- [ ] 电子照 Tab：历史生成记录（本地缓存）
- [ ] 激励视频广告组件接入（高清解锁）
- [ ] 收藏引导横幅（添加到我的小程序）
- [ ] （企业主体）微信支付下单与回调
- [ ] 人像位置默认值调优（头顶/下巴比例按规格适配）
- [ ] 分享卡片、客服入口、意见反馈

### M3 增值功能（约 10 个工作日）

- [ ] 排版照生成（6 寸 1800×1200 @300dpi 自动排 N 张）
- [ ] 轻度美颜（磨皮/美白，Canvas 或 WebGL 滤镜）
- [ ] 正装换装模板合成
- [ ] 冲印下单（供应商 API 对接）

## 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 抠图模型效果不佳（发丝边缘） | 成品质量差 | 边缘羽化 + 引导用户纯色背景拍摄；备选商用 API |
| 个人主体无法开通支付 | 变现受限 | 先广告变现，后续迁移企业主体 |
| 类目不通过 | 上架延期 | 提前准备类目材料，避免人脸识别相关描述 |
| 服务端推理慢 | 用户流失 | 队列 + 前端 loading 动画；预热常驻实例 |
